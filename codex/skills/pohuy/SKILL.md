Контроллер находится в `../../pohuy.py`; разрешай путь относительно этого файла.
Хуки плагина автоматически загружают общий стиль. Этот скилл управляет настройками.

Веди настройку и диагностику на русском, включая ответы до загрузки хука.
Это относится и к автоматически созданному англоязычному запросу setup.
Явный запрос пользователя на другой язык имеет приоритет. Правила оформления
проектных артефактов остаются отдельными от языка настройки.

## Выбор и проверка режима

Этот скилл также служит сценарием setup плагина. Setup, вызов без режима и просьба
настроить Pohuy должны открыть выбор, а не завершиться показом статуса.
Явная просьба проверить статус не открывает выбор и не меняет настройки.

Возьми точный `data_dir` из строки `Pohuy plugin data directory` последнего
контекста хука. В старом контексте тот же путь есть в аргументе `--data-dir`
префикса команды контроллера. При отсутствии контекста используй диагностику
ниже. Не угадывай каталог данных и не вызывай инструменты с другим путём.
Используй MCP-инструменты `status` и `configure` плагина Pohuy,
если они доступны. Вызов `configure` без `tier` открывает нативную форму выбора
и показывает текущий режим. Передавай `tier` только при явном выборе пользователя.
Не выбирай режим за пользователя, не сохраняй значение по умолчанию автоматически.

- Setup или выбор режима: вызови `configure` с `data_dir`, без `tier`.
- Явный запрос режима: вызови `configure` с `data_dir` и выбранным `tier`.
- Только проверка: вызови `status` с `data_dir`.

Если результат содержит `selectionRequired`, покажи текущий режим и четыре
варианта ниже, затем дождись выбора. Используй доступный инструмент вопросов
с вариантами ответа; если его нет, попроси выбрать режим в чате. Не переходи
в Plan только ради формы. Отсутствие MCP тоже использует этот сценарий.
Отмена оставляет настройки без изменений. При ошибке инструмента сообщи её;
не заявляй об успешном сохранении. Ошибка отображения формы допускает выбор
в чате, но ошибка чтения или записи настроек требует исправления.

После отмены сообщи текущий режим и кратко перечисли доступные варианты.
Не открывай форму повторно. Некоторые неинтерактивные клиенты отменяют её
автоматически; явный запрос режима всё равно позволяет сохранить выбор.

После результата `saved: true` примени возвращённый `context` к текущему ответу
и коротко подтверди выбранный режим. Не раскрывай пользователю внутренний путь
к данным или команды контроллера, если он не просит диагностику.

Варианты:

- `off`, "Выключен": обычное общение без стиля Pohuy.
- `lite`, "Легкий": редкие идиоматические акценты.
- `full`, "Обычный": регулярная инженерная лексика, режим по умолчанию.
- `ultra`, "Интенсивный": больше идиом, включая рифмованные формы из справочника.

`normal` соответствует `off`; в MCP передавай `off`.

## Если MCP недоступен

Возьми команду контроллера и точный аргумент `--data-dir` из последнего контекста
хука Pohuy. `PLUGIN_DATA` гарантированно доступен процессам хуков, но обычные
shell-инструменты могут его не получить. Передавай этот аргумент при каждом
вызове `status` или `set`.
Если контекста хука нет и в shell отсутствует `PLUGIN_DATA`, используй диагностику
ниже. Не угадывай каталог данных и не сохраняй настройки в другом месте.

Для проверки выполни `status`. Для setup или вызова без режима после `status`
открой выбор по сценарию выше. Только после явного выбора выполни `set <mode>`.

После успешной смены примени возвращённый `context` к текущему ответу.
Хук мог уже обработать отдельную команду смены режима; `status` подтвердит
результат без повторной записи. При ошибке контроллера сообщи о ней, не заявляй
об успешном сохранении.

Настройка действует для этого плагина во всех проектах и будущих сессиях.
Последний режим важнее старого контекста Pohuy, в том числе при выключении
через `off`. В проектных артефактах сохраняй принятый язык, стиль и терминологию,
особенно при работе над сторонним проектом. Уже принятый русский язык не требует
отдельного запроса пользователя. Если языковой конвенции нет, используй английский.
Явный запрос пользователя или требования локализации имеют приоритет.

## Если контекст хука отсутствует

Сообщи по-русски, что каталог настроек не получен и настройки не изменены.
Отсутствие контекста само по себе не определяет причину. Проверь доступные
результаты запуска хуков, состояние MCP и хост текущего чата:

- `Failed` или ненулевой код выхода: сообщи ошибку запуска, запроси stderr,
  если он недоступен, и проверь команду хука и интерпретатор на этом хосте.
- `Blocked` из-за доверия: предложи подтвердить доверие хукам этого плагина.
- Хуки отключены: предложи включить их.
- Состояние неизвестно: попроси результат Hook stats; сохрани причину неизвестной.

Кнопка setup может открыть новый чат на локальном хосте. Установка и успешный
запуск через SSH не подтверждают работу на локальном Windows. Проверяй хост
по доступному контексту чата и путям, а не по хосту предыдущей беседы.
После устранения подтверждённой причины открой новый чат для загрузки контекста.

## Миграция со старого установщика

Выполни `migrate` для предварительного просмотра. Каталог выбирается из
`CODEX_HOME`, затем `CODEX_DIR`, затем `~/.codex`; передай `--codex-home`, если
пользователь указал другую установку.
Миграция меняет глобальные файлы инструкций и хуков. Применяй
`migrate --apply`, только когда пользователь запросил или разрешил миграцию.
Перед применением закрой остальные сессии Codex. Сообщи изменённые файлы и
каталог резервных копий из результата команды. После миграции открой новый чат:
уже загруженные старые инструкции остаются в существующем контексте.

Миграция сохраняет чужие инструкции, обработчики в смешанных группах хуков
и старый каталог справочников. Некорректный файл останавливает миграцию до записи.
При необходимости восстановления используй указанные резервные копии.
