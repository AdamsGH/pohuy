# Плагин Codex

Нативный плагин загружает общий стиль Pohuy через `SessionStart` и напоминает
о текущем режиме через `UserPromptSubmit`. Установка не добавляет инструкции
в пользовательский `AGENTS.md` и не регистрирует глобальные хуки.

Плагин использует поддерживаемый формат `.codex-plugin/plugin.json`, чтобы
управляющий скилл мог сосуществовать с интеграциями Claude и Pi. Он читает
`codex/AGENTS-pohuy.md` и существующие справочники напрямую. Источники остаются
общими, отдельные копии для поддержки не нужны.

Иконка использует `docs/assets/pohuy.webp`, то же изображение, что и основной
README. SVG содержит исходное изображение целиком, с прозрачными полями до
квадрата. PNG получается рендерингом этого SVG и служит растровой копией.

## Установка

Нужны Python 3.9 или новее, POSIX shell и клиент Codex с поддержкой marketplace
и командных хуков. Интеграционные тесты проверены на Linux с Codex CLI 0.162.1.
Desktop использует документированный формат плагина, но его интерфейс и
выполнение через SSH требуют отдельной интерактивной проверки. Нативный Windows
и облачная оркестрация этим пакетом не покрыты.

Из клона репозитория собери чистый локальный marketplace в новый каталог:

```bash
python3 codex/package.py /tmp/pohuy-marketplace
codex plugin marketplace add /tmp/pohuy-marketplace
codex plugin add pohuy@pohuy
```

Сохрани каталог marketplace, если планируешь переустановку или обновление.
Для постоянной работы выбери каталог вне `/tmp`. Сборщик отказывается писать
в существующий каталог. Установка из локального marketplace копирует каталог
источника целиком. Сборщик исключает `.git`, `node_modules`, приватные файлы
рабочего окружения и ненужные этому плагину интеграции.

Открой `/hooks`, проверь два хука Pohuy и подтверди доверие их текущим определениям.
Затем начни новый чат. Установка сама по себе не даёт доверия хукам. Если хуки
были отключены, включи `hooks = true` в секции `[features]` конфигурации Codex.
Режим по умолчанию: `full`.

В Desktop каталог `.agents/plugins/marketplace.json` также делает плагин
доступным в разделе Plugins. Перезапусти или обнови клиент, установи Pohuy
из его marketplace, проверь хуки и начни новый чат. Python должен быть доступен
там, где реально выполняются хуки, в том числе на удалённом хосте при работе
через SSH.

Для установки через Personal, как у приватных плагинов, собери отдельный ZIP
без каталога marketplace и сохрани через Plugin Creator:

```bash
python3 codex/package.py /tmp/pohuy --archive /tmp/pohuy.zip
```

Оба пути должны быть новыми. ZIP содержит один плагин. Это отдельная регистрация
в аккаунте: локальная установка через CLI её не создаёт. В карточке доступны
три действия: "Настрой режим общения Pohuy", "Покажи текущий режим Pohuy"
и "Выключи стиль Pohuy". Они запускают запрос в чате; переключатель скилла
управляет доступностью скилла, а не интенсивностью стиля.

Приватная регистрация не разворачивает Python и не заменяет проверку хуков
на хосте выполнения. При работе через SSH устанавливай и проверяй пакет
на выбранном удалённом хосте. Список плагинов аккаунта и локальные marketplaces
хоста могут различаться. До удаления локальной установки проверь хуки новой
установки и перенеси сохранённый режим в её каталог данных.

После публикации этой ветки Git marketplace можно подключить командой
`codex plugin marketplace add smixs/pohuy`. Установка через Git использует
отслеживаемые файлы репозитория. Плагины с lifecycle hooks пока распространяются
вручную, через публичный каталог их не публикуют.

## Обновление изображения карточки

В проверенной связке Codex 0.162.1 и Plugin Creator 0.1.26 обновление ZIP
сохраняло изображения в файлах релиза, но каталог возвращал пустые `logoUrl`
и `composerIconUrl`. Штатный метод app-server `plugin/share/save` с `pluginPath`
чистого пакета и существующим `remotePluginId` зарегистрировал обе картинки.
При обновлении этим методом не передавай `discoverability` и `shareTargets`:
доступ остаётся прежним. Не создавай новый плагин ради обновления изображения.

После сохранения проверь карточку через `plugin/read`: обе ссылки должны быть
непустыми и отдавать выбранное изображение. Наличие файла в ZIP или успешная
загрузка релиза сами по себе не подтверждают обновление картинки в каталоге.

## Управление стилем

Открой сценарий setup в карточке установленного плагина или вызови
`$pohuy:pohuy` без аргументов. Можно также попросить "Настрой Pohuy".
Скилл открывает нативную форму: текущий режим, четыре варианта с описаниями,
сохранение после выбора. Отмена оставляет прежний режим.

Форма использует локальный MCP-сервер `pohuy-settings`, включённый в пакет.
Он работает через stdio на Python без дополнительных зависимостей,
не использует сеть и не требует авторизации. Если клиент не поддерживает формы
или MCP отключён, скилл показывает варианты в чате и ждёт выбора.
Запрос "Покажи текущий режим Pohuy" только проверяет статус.
В Codex 0.162.1 политика `never` автоматически отменяет MCP-формы, вызванные
моделью. Скилл сообщает текущий режим и варианты без повторного открытия формы;
выбери режим обычным сообщением. Для использования формы нужны интерактивный
клиент и политика, допускающая вопросы пользователю.

| Режим | Название | Поведение |
| --- | --- | --- |
| `off` | Выключен | Обычное общение без стиля Pohuy. |
| `lite` | Легкий | Редкие идиоматические акценты. |
| `full` | Обычный | Регулярная инженерная лексика. Режим по умолчанию. |
| `ultra` | Интенсивный | Больше идиом, включая рифмованные формы. |

Для прямого выбора по-прежнему можно указать режим:

```text
$pohuy:pohuy lite
$pohuy:pohuy full
$pohuy:pohuy ultra
$pohuy:pohuy off
```

`normal` соответствует `off`. Явная просьба вроде "Включи легкий режим Pohuy"
также может активировать скилл и сохранить выбранный режим без открытия формы.

Хук ввода распознаёт отдельные команды `$pohuy:pohuy <mode>`, `$pohuy <mode>`
и `/pohuy <mode>`. Обработка slash-команд зависит от клиента; в Codex используй
вызов скилла с пространством имён. Команда внутри блока кода, цитаты или более
широкой задачи автоматически не меняет сохранённый режим.

Смена режима действует на текущий ответ и будущие сессии во всех проектах.
Уже открытый чат увидит изменение из другого чата при следующем сообщении
пользователя и при необходимости загрузит полный стиль заново. Обычные сообщения
получают короткое напоминание. `SessionStart` восстанавливает стиль при запуске,
возобновлении, очистке и сжатии контекста. Автоматическое сжатие посреди хода
обрабатывает тот же хук.

Хуки получают точный путь `PLUGIN_DATA`. Настройки хранятся там в `settings.json`;
запись атомарная, права доступа приватные. Небольшие файлы в `sessions/` отмечают,
какой режим получил каждый чат, чтобы восстановить стиль после смены режима
в другом чате. Внутри только название режима, имена файлов содержат хеш
идентификатора сессии. Хук передаёт модели точную команду контроллера, поскольку
shell-инструменты и MCP-процессы не обязаны наследовать `PLUGIN_DATA`.
MCP-инструменты получают точный `data_dir` из контекста хука; отдельного файла
настроек для формы нет. Не включай MCP отдельно от плагина: setup требует
контекста доверенного хука. Если контекста нет, скилл сообщает, как включить
хуки и открыть новый чат, и ничего не записывает.

Конфигурация MCP находится в `codex/mcp.json` и подключается только манифестом
Codex. Сервер не добавляется автоматически к интеграции Claude этого репозитория.

`onboardingSkill` объявлен в `extensions.com.openai` манифеста и указывает
на тот же управляющий скилл. Этот вход запускает настройку в чате, а не добавляет
постоянную панель настроек в приложение. MCP elicitation предоставляет форму
при вызове инструмента. Расширение ChatGPT Plugin settings здесь не используется:
его доступность в Codex Desktop не подтверждена.

Для прямого вызова контроллера возьми префикс команды из контекста хука и добавь
`status` или `set <mode>`. Аргумент `--data-dir` передаётся перед подкомандой.
Контроллер не угадывает каталог данных плагина. Некорректные настройки остаются
нетронутыми, команда возвращает ошибку. Исправь или восстанови файл перед сменой
режима. Ошибка хука не блокирует инженерную задачу; общение продолжается
в обычном режиме.

Стиль Pohuy меняет только обычный текст в чате. Проектные артефакты сохраняют
принятый язык, стиль и терминологию, без разговорной ненормативной лексики.
Если проект уже использует русский, отдельный запрос на русский не нужен.
Если языковой конвенции нет, используется английский. Явный запрос пользователя
или требования локализации имеют приоритет. Литералы, цитаты, языковые примеры
и существующие переводы сохраняются. Предупреждения безопасности, потеря данных,
необратимые операции и инструкции восстановления описываются буквально,
без юмора.

## Миграция со старой установки

Старый вариант через `install-codex.sh` продолжает работать. При переходе
на плагин удали прежний глобальный блок инструкций и напоминание, чтобы стиль
не загружался дважды. Перед применением миграции закрой остальные сессии Codex.

Сначала предварительный просмотр, затем применение:

```bash
python3 codex/pohuy.py migrate
python3 codex/pohuy.py migrate --apply
```

Каталог выбирается из `CODEX_HOME`, затем `CODEX_DIR`, затем `~/.codex`.
Для другой установки передай `--codex-home /absolute/path` после `migrate`.
Миграция не требует каталога данных плагина.

Она удаляет завершённые блоки `<!-- pohuy:start -->` / `<!-- pohuy:end -->`
и только точное напоминание, которое создавал старый установщик. Остальные
байты инструкций, события хуков, метаданные групп и чужие обработчики
в смешанных группах сохраняются. Каталог `pohuy/references/` остаётся на месте.

Перед записью команда проверяет оба файла и сохраняет изменяемые оригиналы
в `pohuy-migration-backups/`. Результат содержит путь к резервной копии.
Повторная миграция ничего не меняет. Некорректный JSON, повреждённые маркеры
или файлы-симлинки останавливают миграцию. При ошибке замены уже изменённые
файлы восстанавливаются; резервные копии доступны и при ошибке восстановления.
После миграции открой новые чаты: старые сохраняют уже загруженные инструкции.

Для отмены миграции скопируй `AGENTS.md` и/или `hooks.json` из указанного
каталога резервных копий в тот же каталог конфигурации Codex при закрытых сессиях.
Сохраняются только файлы, которые эта миграция изменила.

## Отключение и удаление

Режим `off` оставляет контроллер доступным и возвращает обычное общение.
Для отключения плагина целиком установи `enabled = false` в секции
`[plugins."pohuy@pohuy"]` конфигурации Codex и начни новый чат. Удаление:

```bash
codex plugin remove pohuy@pohuy
codex plugin marketplace remove pohuy
```

Отключение или удаление хуков не убирает инструкции из уже открытого чата.
Начни новый чат после отключения или удаления плагина. Старые глобальные
инструкции удаляются отдельно через команду миграции.

## Проверки

```bash
npm run test:codex
npm run test:codex:integration
npm test
npm run typecheck
```

Интеграционный тест устанавливает чистый пакет во временный `CODEX_HOME`,
запускает настоящий Codex и перехватывает запросы модели локальным mock-сервером
Responses. Он проверяет обнаружение скилла, контекст хуков, сохранение режимов,
возобновление сессии и границу доверия хукам. Проверка через app-server также
подтверждает setup-вход, подключение MCP, форму с четырьмя вариантами, сохранение
выбора и отсутствие записи при отмене или отказе. Живая модель не вызывается,
пользовательская установка Codex не меняется. Доверие хукам обходится только
в изолированных запусках, которые проверяют этот пакет.

Остальные тесты проверяют события сжатия контекста, повреждённые настройки,
конкурентную запись, точное удаление старой установки, резервные копии и откат.
Качество стиля в живом разговоре и поведение интерфейса Desktop проверяются
отдельно вручную.
