# Плагин Codex

Плагин реализован на TypeScript. Пакет содержит собранные JavaScript-файлы,
работающие в Node.js 22.19 или новее. Python и установка npm-зависимостей
на хосте выполнения не требуются. Node.js должен быть доступен команде `node`
на том хосте, где выполняются инструменты и хуки.

## Компоненты

- `settings.read({})` читает схему, текущие значения и layout нативных настроек.
- `settings.update({set: {mode}})` сохраняет выбранный режим и отдельно выбранные параметры.
- `pohuy.context({})` возвращает сохранённый режим и инструкции текущему чату.
- `SessionStart` и `UserPromptSubmit` автоматически загружают и восстанавливают стиль.
- Отдельный скилл `setup` проводит первоначальную настройку, а `pohuy` проверяет
  и меняет режим.

Сервер объявляет `openai/settings` через официальный TypeScript SDK
`@openai/mcp-extensions`. Хост с поддержкой расширения может отобразить выбор
режима и дополнительных параметров в карточке плагина. Объявление capability не гарантирует
отображение панели в каждом клиенте. При отсутствии панели те же инструменты
доступны через скилл. Настройка работает без контекста хука.

## Стиль и настройки

Codex использует тот же разборщик `extensions/pohuy/style-source.ts`, что и Pi.
Уровни, правила, словарь и примеры берутся из `skills/pohuy/SKILL.md` и
`references/`. Отдельного пересказа стиля для Codex нет. Изменение исходника
попадает в обе интеграции при следующей сборке.

В карточке доступны уровни `lite`, `full`, `ultra` и выключение, применение
с начала чата, объём ответа и шутки по делу. Четыре переключателя соответствуют
файлам `slovar.md`, `sceny.md`, `huenitiv.md` и `ontologia.md`.
Общий разборщик собирает правила, словарь и сцены в готовый промпт.
Выбранные материалы включаются сразу; агенту не нужно открывать файлы. Хуенитивы доступны в `ultra`. Онтология по умолчанию
отключена. Основные правила и примеры выбранного уровня остаются обязательными.

При выключенном "Pohuy с начала чата" команда `/pohuy full` применяет стиль
к отдельному ответу. Выбранный уровень и остальные настройки сохраняются.
Изменения параметров обновляют контекст на следующем ходе. Настройки разных
хостов независимы. Старые файлы версии 1 читаются без перезаписи; обновление
меняет только переданные поля. Обозначения уровня в MCP теперь совпадают
с исходником, а значения `tier` на диске остались прежними.

Дополнительный переключатель "Короткие тире" по умолчанию выключен. Он заменяет
длинное тире на ASCII-дефис только в обычном тексте собранного промпта.
Кодовые блоки, inline-код и ссылки сохраняются. Файлы исходного скилла и
справочников не меняются. Настройка действует и на короткие напоминания хуков.

## Структура исходников

- `src/`: MCP-сервер, контроллер, настройки, композиция и миграция.
- `scripts/`: сборка, упаковка и генерация промпта для старого установщика.
- `hooks/`: определения хуков.
- `skills/`: настройка и управление плагином.
- `tests/` и `schemas/`: проверки и схемы манифестов.
- `dist/`: результат сборки, исключённый из git.

`AGENTS-pohuy.md` не требуется. Старый установщик тоже получает готовый промпт
из общего разборщика; для его запуска нужен Node.js 22.19 или новее.

## Манифест

Корневой `plugin.json` содержит идентификатор и переносимые компоненты;
`extensions.com.openai` содержит `interface`, `hooks` и `onboardingSkill`.
Корневой `mcp.json` объявляет stdio-сервер. `.codex-plugin/plugin.json`
и `codex/mcp.json` сохраняют совместимость с клиентами старого формата.
Inline-блок OpenAI заменяет compatibility overlay целиком.
Сборщик переносимого пакета размещает управляющие скиллы в корневом `skills/`.
В исходном репозитории они лежат в `codex/skills/`, чтобы не менять скилл Claude.
Для установки собирай пакет, а не передавай checkout как переносимый плагин.

## Сборка и установка

`codex/dist/` создаётся сборкой и не отслеживается в git. Установочный ZIP
содержит готовый Node.js-код и лицензии зависимостей, поэтому пользователю
не нужен npm. Для отсутствующей в npm-пакете лицензии `@cfworker/json-schema`
сборщик обращается к закреплённому коммиту исходного репозитория и проверяет SHA-256.
Этот шаг сборки требует доступа к `raw.githubusercontent.com`.
Исходный скилл копируется в пакет без изменений в
`codex/style/SKILL.md`, отдельно от управляющих скиллов.


Из клона репозитория:

```bash
npm ci
npm run package:codex -- /tmp/pohuy-marketplace --compat
codex plugin marketplace add /tmp/pohuy-marketplace
codex plugin add pohuy@pohuy
```

Каталог назначения должен быть новым. Сохрани его для обновления установки,
для постоянной работы выбери каталог вне `/tmp`. Сборщик копирует только
явно перечисленные файлы и не включает `.git`, приватные данные и `node_modules`.

Для ZIP регистрации в аккаунте:

```bash
npm run package:codex -- /tmp/pohuy --archive /tmp/pohuy.zip
```

Оба пути должны быть новыми. ZIP содержит один плагин без каталога marketplace.
Для клиентов, не обнаруживающих хуки переносимого манифеста, добавь `--compat`:
такой пакет содержит прежний compatibility-манифест без корневого `plugin.json`.
Это вариант упаковки того же сервера и тех же хуков.
В Codex 0.162.1 установка проверена с `--compat`. В изолированной проверке
клиент обнаружил 0 хуков переносимого пакета и 2 хука compatibility-пакета.
Переносимый манифест проходит официальную JSON Schema. Для выпуска на этот
клиент используется compatibility-пакет, пока обнаружение хуков не исправлено.

Регистрация через Personal хранит собственный релиз. Website открывает страницу
проекта; публикация Git-ветки и смена этой ссылки не обновляют пакет аккаунта.
После сохранения нового релиза обнови установку на нужном хосте.

## Хост выполнения и данные

Хук использует переданный Codex `PLUGIN_DATA`. Сервер использует `PLUGIN_DATA`
или явно заданный `POHUY_DATA_DIR`. В Codex 0.162.1 переменная `PLUGIN_DATA`
не передаётся MCP-процессу. Для установленного пакета сервер проверяет фактический
путь `plugins/cache/<marketplace>/pohuy/<version>` и выбирает соответствующий
`plugins/data/pohuy-<marketplace>`. При запуске вне cache требуется явный
`POHUY_DATA_DIR`. Модель не передаёт пути к файлам через инструменты настройки.

Режим хранится в `settings.json`, формат `{"version":1,"tier":"full"}`.
Отсутствующий файл означает `full` без записи. Некорректный файл сохраняется
для исправления. Неизвестные поля остаются при обновлении режима. Запись атомарна.
Хуки и MCP читают один файл; выбор в карточке становится доступен другим чатам
на следующем ходе. Данные между хостами не синхронизируются.

Setup может открыть локальный чат на Windows даже после работы через SSH.
Проверка на удалённом Linux не подтверждает запуск на Windows. Для Windows
задан отдельный `commandWindows` для стандартного `cmd.exe` launcher хуков.
Это отдельно от PowerShell, используемого инструментами чата. После изменения
определения хука Codex требует доверия к его новому hash.

## ChatGPT и контекст

Локальный stdio-сервер требует хоста с Node.js. Загрузка ZIP в аккаунт не
разворачивает этот процесс в облаке. Structured Settings описаны для ChatGPT
Work; поддержка в конкретном Codex Desktop проверяется отдельно. Для удалённого
ChatGPT-сервера нужны отдельное размещение, авторизация и хранилище пользователя.
Этот пакет не публикует неавторизованный HTTP endpoint.

`ui/update-model-context` из Apps SDK меняет контекст текущего чата. Он не
сохраняет режим и не обеспечивает автоматическое применение во всех будущих
чатах. Здесь настройки сохраняет сервер, текущий чат получает инструкции через
`pohuy.context`, а автоматическую загрузку обеспечивают хуки локального Codex.

## Миграция

Контроллер принимает `--data-dir <абсолютный каталог>` для `status` и `set`.
Для миграции каталог настроек плагина не требуется:

```bash
node codex/dist/controller.mjs migrate
node codex/dist/controller.mjs migrate --apply
```

Первый вызов только показывает изменения. Применяй миграцию по запросу
пользователя, после закрытия других писателей конфигурации. `--codex-home`
выбирает старую установку явно; иначе используются `CODEX_HOME`, `CODEX_DIR`
или `~/.codex`. Миграция удаляет только полные блоки Pohuy и точный старый
обработчик напоминания. Она сохраняет чужие инструкции и хуки, отказывается
заменять symlink, проверяет изменения перед записью, создаёт резервные копии
и восстанавливает уже заменённые файлы при ошибке. Справочники остаются.

## Проверка

```bash
npm run typecheck:codex
npm run test:codex
```

Тесты проверяют настоящий stdio MCP через SDK-клиент, объявление capability,
схему и layout, сохранение и отказ на некорректных значениях, общий файл хуков,
упаковку и миграцию. Проверка протокола отдельно от ручной проверки отображения
панели и реального выполнения хуков на Windows.
